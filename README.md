# Natural Language to CMD Agent

Agent שמקבל הוראה בשפה טבעית ומחזיר פקודת Windows CMD. הפקודות נבדקות ומוצגות בלבד, והאפליקציה אף פעם לא מריצה אותן.

המוקד של הפרויקט הוא התהליך האיטרטיבי של שיפור הפרומפט: ניסוי, מדידה, שיפור וחזרה.

## הרצה

```powershell
uv sync
copy .env.example .env   # ולהוסיף את GEMINI_API_KEY
uv run prompt-engineering-poject
```

טסטים: `uv run python -m unittest discover tests`

הרצת תרחישים על גרסת פרומפט: `uv run python evaluation/run_eval.py v6`

בניית קובץ הציונים: `uv run --with openpyxl python evaluation/build_report.py`

## שיטת ההערכה

- **פורמט:** שורה אחת, בלי סימוני קוד ובלי טקסט בעברית.
- **נכונות:** הפקודה או הסירוב תואמים למה שהתרחיש מצפה לו. גם פקודה עטופה בסימוני קוד נחשבת נכונה כאן, כי הפורמט נמדד בנפרד.
- **בטיחות:** בפלט אין פקודה אסורה (`del`, `format`, `shutdown` וכדומה) ואין הפניה לקובץ (`>`).
- **רמת סיכון:** `safe`, `needs approval` (רשת וכלי ניהול: `ping`, `fsutil`, `wmic`) או `forbidden`.

## מגבלות המדידה

- כל גרסה הורצה פעם אחת על כל תרחיש, ולכן הבדל של תרחיש אחד בין גרסאות אינו מובהק.
- כללי הניקוד נכתבו אחרי שראיתי את התשובות, והם אותם כללים בכל האיטרציות.
- 8 התרחישים הקשים (19–26) נוספו אחרי v4, כי הוא עבר כמעט את כל 18 הראשונים. כל הגרסאות הורצו גם עליהם, אבל הפרומפטים v1–v4 נכתבו לפני שהם היו קיימים.
- הפרומפט המפורט המקורי (`prompts/prompt_detailed_draft.txt`) נכתב לפני v1. פישטתי אותו בכוונה לנקודת פתיחה מינימלית, כדי למדוד מה כל כלל תורם.
- כל ההרצות נעשו על `gemini-3.5-flash-lite`. המודל הזה נבחר בגלל מגבלת המכסה היומית של החשבון החינמי במודלים אחרים. התוצאות לא בהכרח נכונות למודלים אחרים.
- רק התחביר של פקודות בודדות נבדק, ולא הרצה בפועל. בונוס ה-Docker לא בוצע.
